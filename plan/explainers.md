## 1. Python 2 与 Python 3 的区别

### 是什么

Python 3 于 2008 年发布，与 Python 2 不完全兼容；Python 2 已于 2020 年 1 月 1 日停止维护。网上较早的 CTF 题解很多是 Python 2 写的，直接用 Python 3 运行常常报错。

### 对 CTF 影响最大的四个区别

| 区别 | Python 2 | Python 3 | CTF 中的影响 |
|---|---|---|---|
| 字符串 | `"abc"` 是字节串（`str`），`u"abc"` 才是文本 | `"abc"` 是文本（`str`），`b"abc"` 才是字节串（`bytes`） | 加解密、编码函数在 Python 3 中大多要求传入 `bytes`，传 `str` 会报 `TypeError` |
| 取字节串的一项 | `b"flag"[0]` 得到 `'f'` | `b"flag"[0]` 得到 `102` | 旧脚本中的 `ord(s[i])` 在 Python 3 中会报错 |
| `print` | 语句：`print "hi"` | 函数：`print("hi")` | 旧脚本最常见的报错 |
| 除法 | `7 / 2` 得 `3` | `7 / 2` 得 `3.5` | RSA 等大数计算中用 `/` 会得到浮点数，丢失精度；**整数除法一律写 `//`** |

另外，Python 2 默认按 ASCII 读取源文件，脚本中只要有中文（包括注释），就会报 `SyntaxError: Non-ASCII character`，需要在第一行加上：

```python
# -*- coding: utf-8 -*-
```

编写本计划的示例脚本时，Python 2 就报了这个错误。Python 3 默认按 UTF-8 读取，不需要这一行。

### 两个版本都能运行的写法

```python
# -*- coding: utf-8 -*-
from __future__ import print_function, division   # 让 Python 2 的 print 和除法与 Python 3 一致

s = b"flag"
print(bytearray(s)[0])     # 两个版本都得到 102；bytearray 是两个版本行为一致的字节类型
print(7 / 2, 7 // 2)       # 两个版本都得到 3.5 3
```

完整示例：[snippets/01_py2_vs_py3.py](snippets/01_py2_vs_py3.py)。

- Docker 环境中的 `python2` 命令：来不及改的旧脚本可以直接运行。

## 2. Base64 编码

### 是什么

Base64 把任意字节转换成 64 个可打印字符（`A-Z`、`a-z`、`0-9`、`+`、`/`），用于在只能传输文本的地方（邮件、网页、JSON）传输二进制数据。它是**编码**，不是加密，没有密钥，任何人都能还原。

### 原理

1. 把输入的字节按顺序写成二进制，每 3 个字节是 24 位；
2. 每 6 位一组，分成 4 组，每组的值是 0～63；
3. 每个值去码表里查对应的字符；
4. 最后不足 3 个字节时，用 `0` 补足位数，并在结果末尾加 `=`，保证结果长度是 4 的倍数。

以 `fla` 为例：

```
字符        f          l          a
十六进制    66         6C         61
二进制      01100110   01101100   01100001
每 6 位     011001  100110  110001  100001
十进制      25      38      49      33
查表        Z       m       x       h          → "Zmxh"
```

### 怎么认出来

- 只包含 `A-Z a-z 0-9 + /`，末尾可能有 1～2 个 `=`；
- 长度是 4 的倍数；
- **`flag` 编码后以 `Zmxh` 开头，`flag{` 编码后以 `ZmxhZ` 开头**，看到这几个字符基本可以确定。

### 代码

```python
# -*- coding: utf-8 -*-
from __future__ import print_function
import base64

TABLE = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/"

def b64encode(data):
    bits = "".join("{:08b}".format(b) for b in bytearray(data))   # 每个字节写成 8 位二进制
    bits += "0" * (-len(bits) % 6)                                 # 补 0 到 6 的倍数
    out = "".join(TABLE[int(bits[i:i + 6], 2)] for i in range(0, len(bits), 6))
    return out + "=" * (-len(out) % 4)                             # 补 = 到 4 的倍数

msg = u"flag{你好}".encode("utf-8")
print(b64encode(msg))                                   # ZmxhZ3vkvaDlpb19
assert b64encode(msg) == base64.b64encode(msg).decode("ascii")
```

完整示例：[snippets/02_base64.py](snippets/02_base64.py)。

### 常见变形

- **换表 Base64**：题目把 `TABLE` 换成打乱顺序的 64 个字符。只要知道新码表，把上面代码中的 `TABLE` 换掉即可。逆向题中常在程序里找到一段 64 个字符的字符串，就是新码表。
- **多层编码**：解开一层后仍是 Base64 或其他编码，需要反复解。工具包的“智能识别”会自动递归尝试。
- **Base64 隐写**：利用解码时被忽略的补位 `0` 藏数据，需要逐段提取最后几位。

## 3. 凯撒密码与枚举

### 是什么

凯撒密码把每个字母在字母表中向后移动固定的位数（密钥 k）。k = 3 时，`a` 变 `d`，`z` 变 `c`。ROT13 就是 k = 13 的凯撒密码。

### 为什么容易破解

英文字母只有 26 个，所以密钥只有 26 种可能。**把 26 种全部试一遍**（枚举），看哪一行是有意义的文字即可。这是密码学中最基本的思路：密钥空间太小，就直接枚举。

### 代码

```python
import string

def caesar(text, k):
    out = []
    for c in text:
        if c in string.ascii_lowercase:
            out.append(chr((ord(c) - 97 + k) % 26 + 97))   # 97 是 'a' 的 ASCII 码
        elif c in string.ascii_uppercase:
            out.append(chr((ord(c) - 65 + k) % 26 + 65))   # 65 是 'A' 的 ASCII 码
        else:
            out.append(c)                                   # 非字母原样保留
    return "".join(out)

for k in range(26):
    print(k, caesar("synt{pnrfne}", k))    # 第 13 行是 flag{caesar}
```

完整示例：[snippets/03_caesar.py](snippets/03_caesar.py)。

### 常见变形

- **只看到 `synt`**：`flag` 经 ROT13 后是 `synt`，看到 `synt{` 可以直接试 ROT13。
- **结果不是英文单词**：工具包按英文字母频率（`e`、`t`、`a` 最常见）给 26 个结果打分，最像英文的排在最前面。
- **数字和符号也移动了**：可能是 ROT47（对 ASCII 33～126 的全部可打印字符移动 47 位）。

## 4. ZIP 伪加密

### 是什么

ZIP 文件中每个文件的记录里都有一个“通用位标记”（General purpose bit flag），它的最低位表示“这个文件是否加密”。解压软件看到这一位是 1，就会要求输入密码。

**伪加密**是指：文件数据其实没有加密，只是把这一位改成了 1，让解压软件误以为需要密码。

### 标记位的位置

| 记录 | 标识（文件中的字节） | 标记位的偏移 |
|---|---|---|
| 本地文件头 | `50 4B 03 04`（`PK\x03\x04`） | 第 6～7 字节 |
| 中央目录记录 | `50 4B 01 02`（`PK\x01\x02`） | 第 8～9 字节 |

每个文件在两处各有一个标记位，伪加密可能只改了其中一处，也可能两处都改了。

### 怎么判断真假

- 真加密的文件，数据前面有 12 字节的加密头，压缩数据本身也是乱的；
- 伪加密的文件，把标记位清零后可以正常解压。

所以最简单的判断方法是：**先把标记位全部清零，能解压就是伪加密。**

### 代码

```python
def unfake(data):
    """把所有记录的加密位清零，返回修复后的字节"""
    data = bytearray(data)
    for sig, off in ((b"PK\x03\x04", 6), (b"PK\x01\x02", 8)):
        i = 0
        while True:
            i = data.find(sig, i)
            if i < 0:
                break
            data[i + off] &= 0xFE      # 0xFE = 11111110，只清最低位，其他位不动
            i += 4
    return bytes(data)
```

完整示例（脚本自己生成一个伪加密压缩包，再修复并读出内容）：[snippets/04_zip_fake_encrypt.py](snippets/04_zip_fake_encrypt.py)。

### 注意

按 `PK\x03\x04` 搜索是简化做法，压缩数据中恰好出现这几个字节时会误改。工具包中的正式版本会先从文件末尾的“中央目录结束记录”读出每条记录的准确位置，再逐条修改。

## 5. PNG 宽高修复

### 是什么

PNG 文件开头是 8 字节的固定签名，紧接着是 `IHDR` 块，记录图片的宽度、高度等信息。出题人把高度改小后，图片只显示上半部分，flag 藏在被“裁掉”的下半部分。

### 结构

```
偏移   长度   内容
0      8      签名 89 50 4E 47 0D 0A 1A 0A
8      4      IHDR 数据长度（固定为 13）
12     4      块类型 "IHDR"
16     4      宽度（大端序）
20     4      高度（大端序）       ← 常被修改
24     5      位深、颜色类型、压缩方法、过滤方法、隔行扫描
29     4      CRC32 校验值（对“块类型 + 数据”共 17 字节计算）
```

### 为什么能找回真实高度

出题人改了高度，但通常没有重新计算 CRC。CRC 仍然是按**原始高度**算出来的。所以只要枚举高度，找到使 CRC 吻合的那个值，就是原始高度。

### 怎么认出来

- Windows 的图片查看器能打开，但 Linux 或浏览器中提示文件损坏（CRC 错误）；
- 工具包的 PNG 结构查看器会直接提示“IHDR 的 CRC 不匹配”。

### 代码

```python
import struct, zlib

def fix_height(png):
    ihdr = png[12:29]                         # "IHDR" + 13 字节数据
    crc, = struct.unpack(">I", png[29:33])    # 文件中记录的 CRC
    w, = struct.unpack(">I", ihdr[4:8])
    for h in range(1, 4096):
        data = ihdr[:8] + struct.pack(">I", h) + ihdr[12:]
        if zlib.crc32(data) & 0xFFFFFFFF == crc:   # & 0xFFFFFFFF：Python 2 的 crc32 可能返回负数
            return w, h
    return None
```

完整示例：[snippets/05_png_height.py](snippets/05_png_height.py)。找到高度后，把文件第 20～23 字节改成正确的值即可。

### 常见变形

宽度也可能被修改。宽度和高度都要枚举时，范围取 1～4096 共约 1600 万种组合，纯 Python 需要几十秒到几分钟（视设备而定），工具包会显示进度条（Progress），并在找到结果后立即停止。

## 6. LSB 隐写

### 是什么

LSB（Least Significant Bit，最低有效位）隐写，是把要隐藏的数据写进每个像素颜色值的最低一位。

一个像素的红色值是 0～255，例如 `10110100`（180）。把最低位改成 1，变成 `10110101`（181）。颜色只差 1，肉眼完全看不出来，但每个像素就能藏 1 位数据（RGB 三个通道就是 3 位）。

### 怎么认出来

- 图片看起来正常，文件尾、元数据里都没有东西；
- 用工具包的“位平面浏览”逐一查看各通道的第 0 位平面（最低位），如果某个位平面的顶部出现一条规律的杂纹，而其他区域是噪点或纯色，说明那里写了数据。

### 原理代码

为了只用标准库，下面把一串字节当作像素数据演示；实际处理图片时，用 `Pillow` 读出像素值即可。

```python
def hide(pixels, secret):
    out = bytearray(pixels)
    bits = "".join("{:08b}".format(b) for b in bytearray(secret))
    for i, bit in enumerate(bits):
        out[i] = (out[i] & 0xFE) | int(bit)   # 清掉最低位，再写入要藏的那一位
    return out

def extract(pixels, length):
    bits = "".join(str(b & 1) for b in bytearray(pixels)[:length * 8])   # 取出每个字节的最低位
    return bytearray(int(bits[i:i + 8], 2) for i in range(0, len(bits), 8))
```

运行完整示例（[snippets/06_lsb.py](snippets/06_lsb.py)）可以看到：藏入 `flag{lsb}` 后，每个值最多只变化 1。

### 提取时要试的参数

LSB 题目难在“按什么顺序写的”。工具包的 LSB 提取工具把这些参数都列成选项：

| 参数 | 常见取值 |
|---|---|
| 通道 | R、G、B、A，或其组合（如 RGB 依次） |
| 位 | 第 0 位（最低位）最常见，也可能是第 1、2 位 |
| 像素顺序 | 按行（从左到右、从上到下）或按列 |
| 位序 | 每 8 位组成一个字节时，先取到的位放在高位还是低位 |

## 7. RSA 基础与小 e 攻击

### 是什么

RSA 是最常见的非对称加密算法：用公钥 `(n, e)` 加密，用私钥 `d` 解密。它的安全性基于“把一个大数 n 分解成两个质数相乘很困难”。

### 计算步骤

| 步骤 | 公式 | 示例（小数字，便于手算） |
|---|---|---|
| 选两个质数 | p、q | p = 61，q = 53 |
| 计算模数 | n = p × q | n = 3233 |
| 计算欧拉函数 | φ(n) = (p − 1)(q − 1) | φ(n) = 3120 |
| 选公钥指数 | e 与 φ(n) 互质 | e = 17 |
| 求私钥 | d = e⁻¹ mod φ(n)，即 e × d ≡ 1 (mod φ(n)) | d = 2753 |
| 加密 | c = mᵉ mod n | m = 65 → c = 2790 |
| 解密 | m = cᵈ mod n | c = 2790 → m = 65 |

CTF 中的 RSA 题，几乎都是在这几步中找到一个“弱点”，绕过“分解 n”这一难题。

### 求私钥的代码

```python
def egcd(a, b):
    """扩展欧几里得算法：返回 (g, x, y)，满足 a*x + b*y = g"""
    if b == 0:
        return a, 1, 0
    g, x, y = egcd(b, a % b)
    return g, y, x - (a // b) * y          # 注意用 //，不能用 /

def inverse(e, phi):
    g, x, _ = egcd(e, phi)
    assert g == 1                           # e 与 φ(n) 必须互质
    return x % phi

p, q, e = 61, 53, 17
n, phi = p * q, (p - 1) * (q - 1)
d = inverse(e, phi)                         # 2753
print(pow(pow(65, e, n), d, n))             # 先加密再解密，得到 65
```

Python 3.8 以上可以直接写 `pow(e, -1, phi)` 求模逆，但 Python 2 不支持，所以这里手写。

### 小 e 攻击

如果 e 很小（比如 3），明文 m 也不长，可能出现 mᵉ < n。这时“mod n”根本没有起作用，**密文 c 就等于 mᵉ 本身**，直接对 c 开 e 次方就得到明文，不需要私钥。

```python
def iroot(x, k):
    """整数 k 次方根（二分查找）。不能用 x ** (1/3)：浮点数精度不够，大数会算错"""
    lo, hi = 0, 1 << (x.bit_length() // k + 1)
    while lo < hi:
        mid = (lo + hi + 1) // 2
        if mid ** k <= x:
            lo = mid
        else:
            hi = mid - 1
    return lo
```

完整示例（含把整数转回字节串的两版本通用写法）：[snippets/07_rsa.py](snippets/07_rsa.py)。

### 其他常见弱点（工具包都会提供）

| 弱点 | 条件 | 方法 |
|---|---|---|
| n 太小 | n 只有几十位 | 直接分解，或查询 factordb |
| p、q 太接近 | \|p − q\| 很小 | 费马分解 |
| 共模攻击 | 同一明文、同一 n、两个互质的 e | 扩展欧几里得组合两个密文 |
| 公因数 | 多个 n 共用一个质数 | 两两求最大公因数 |
| d 太小 | d < n^0.25 / 3 | Wiener 攻击（连分数） |
| 广播攻击 | 同一明文用相同的小 e 发给多个人 | 中国剩余定理合并后开方 |

## 8. PHP 弱类型比较

### 是什么

PHP 有两种比较：`==`（松散比较，会先转换类型再比较）和 `===`（严格比较，类型和值都要相同）。用 `==` 比较时，类型转换的规则会带来一些违反直觉的结果，这就是“弱类型”问题。

### 比较结果速查

**PHP 8 修改了数字与非数字字符串的比较规则**，同一道题在 PHP 7 和 PHP 8 上结果可能不同。做题前先确认题目的 PHP 版本（响应头 `X-Powered-By` 或报错信息中常能看到）。

| 表达式 | PHP 7 | PHP 8 | 原因 |
|---|---|---|---|
| `0 == "abc"` | `true` | `false` | PHP 7 把 `"abc"` 转成数字 0；PHP 8 改为把 0 转成字符串 `"0"` 再比较 |
| `"1" == "01"` | `true` | `true` | 两边都是数字字符串，按数值比较 |
| `"10" == "1e1"` | `true` | `true` | `1e1` 是科学计数法，等于 10 |
| `"0e123" == "0e456"` | `true` | `true` | 两边都是“0 的若干次方”，都等于 0 |
| `null == false` | `true` | `true` | 都转为布尔值 `false` |
| `"abc" == "ABC"` | `false` | `false` | 都不是数字字符串，按字符串比较 |

### 典型考法：0e 开头的哈希值

```php
if ($_GET['a'] != $_GET['b'] && md5($_GET['a']) == md5($_GET['b'])) {
    echo $flag;
}
```

需要两个不同的字符串，MD5 值“相等”。由于 `==` 会把 `0e` 后面全是数字的字符串当作 0，只要找到两个 MD5 值都是 `0e` + 30 位数字的字符串即可：

| 字符串 | MD5 |
|---|---|
| `240610708` | `0e462097431906509019562988736854` |
| `QNKCDZO` | `0e830400451993494058024219903391` |

（上表的 MD5 值已用 Python `hashlib` 验证。）

另一种常见解法是传数组（`?a[]=1&b[]=2`）：PHP 7 中 `md5()` 收到数组会报警告并返回 `NULL`，两边都是 `NULL` 所以相等；**PHP 8 中 `md5()` 收到数组会直接抛出 `TypeError` 终止运行，这种解法不再有效。**

### 防御方法

工具包的讲解会同时写出修复方式：比较一律使用 `===`；比较哈希值、令牌使用 `hash_equals()`；对输入先做类型检查。

## 9. 栈溢出与保护机制

### 是什么

函数被调用时，会在栈上开辟一块空间（栈帧），存放局部变量，以及函数结束后要回到哪里（返回地址）。如果程序往局部数组里写入的数据超过了数组的大小，多出来的部分就会覆盖后面的数据，包括返回地址。攻击者控制了返回地址，就控制了程序接下来执行什么，这就是栈溢出。

### 一个最简单的例子

```c
#include <stdio.h>

void vuln(void) {
    char buf[16];
    gets(buf);          /* gets 不检查长度，输入多长就写多长 */
}

int main(void) {
    vuln();
    return 0;
}
```

32 位程序中 `vuln` 的栈帧（地址从上往下增大）：

```
低地址
┌─────────────────────┐ ← buf 起始
│ buf[16]             │   输入从这里开始写
├─────────────────────┤
│ （编译器可能留的空隙） │
├─────────────────────┤
│ 保存的 ebp（4 字节）  │
├─────────────────────┤
│ 返回地址（4 字节）    │ ← 覆盖这里，函数返回时就会跳到我们指定的地址
└─────────────────────┘
高地址
```

从 `buf` 起始到返回地址之间到底有多少字节，取决于编译器，不能只靠数数组大小来推算。工具包的 **cyclic** 工具生成一串不重复的模式字符串，程序崩溃时看返回地址被覆盖成了哪 4 个字节，就能反查出准确的偏移。

### 保护机制

现代系统和编译器加了多种保护。拿到题目先用 checksec 查看开启了哪些，再决定利用方法：

| 保护 | 作用 | 开启后的影响 | 常见应对 |
|---|---|---|---|
| **NX**（栈不可执行） | 栈上的数据不能当作代码执行 | 不能把 shellcode 写在栈上直接执行 | ROP、ret2libc：复用程序和 libc 里已有的代码 |
| **Canary**（栈保护） | 在局部变量与返回地址之间放一个随机值，函数返回前检查是否被改动 | 直接覆盖返回地址会被检测到，程序终止 | 先通过其他漏洞（如格式化字符串）泄露这个值，溢出时原样写回 |
| **PIE**（地址无关可执行文件） | 程序每次加载到随机地址 | 不知道程序中函数和 gadget 的实际地址 | 先泄露一个程序内的地址，算出加载基址 |
| **ASLR**（系统级地址随机化） | 栈、堆、libc 每次加载到随机地址 | 不知道 `system` 等函数的地址 | 先泄露一个 libc 函数的地址，减去偏移得到 libc 基址 |
| **RELRO** | Partial：GOT 表的部分区域只读；Full：程序启动时解析完全部函数地址，整个 GOT 表只读 | Full RELRO 下无法通过改写 GOT 表劫持函数 | 改为覆盖返回地址、`__free_hook`（glibc 2.34 之前）等其他目标 |

### 练习环境

上面的例子用以下命令编译，可以关闭各项保护，从最简单的情况开始练习（在 Docker 环境中执行，不要在自己的主力系统上运行有漏洞的程序）：

```bash
gcc -m32 -fno-stack-protector -no-pie -z execstack -o vuln vuln.c
```

逐项去掉这些参数，就能依次体验每一种保护带来的变化。这也是例题库第 6 章的编排顺序（见 [range.md](range.md)）。
