# 靶场与例题规划

[← 返回计划总览](README.md)

本文是后续工作的规划，排在工具包主体之后：**例题库在 v0.9 完成，靶场在 v1.x 开始**。现在先确定格式与原则，使工具包在设计时就为它们预留好位置。

---

## 1. 两者的区别

| | 例题 | 靶场 |
|---|---|---|
| 形式 | 一个附件（图片、压缩包、密文、程序）+ 题面 | 一个需要运行的服务（网站、网络服务、模拟 PLC） |
| 运行位置 | 三端都能做，不需要联网 | 用户自己电脑上的 Docker |
| 适合的方向 | 杂项、隐写、密码学、逆向、PWN 的静态分析部分 | Web、PWN 的远程利用、工控 |
| 验证 flag | 在本机离线验证 | 每次启动生成新的 flag，本机验证 |
| 完成版本 | v0.9 | v1.x |

## 2. 例题库

### 2.1 原则

- **全部原创**：题目、附件、题解都由本项目编写，不复制参考教材或其他比赛的题目。改编公开比赛的题目时，需取得原作者授权并注明出处。
- **一题一个知识点**：每道入门题只考一个知识点，题解指向对应的讲解与工具，做完一道题就学会一个工具。
- **由易到难**：每节按“入门 → 基础 → 进阶”三档编排，进阶题才组合多个知识点。
- **题解必须可复现**：题解中的每一步都能用工具包或 Docker 环境中的工具完成；题解中的脚本提供 Python 3 版本，必要时附 Python 2 版本，并在持续集成中运行验证。

### 2.2 题目格式

每道题一个目录：

```
content/challenges/misc/zip-fake-encrypt-01/
├── challenge.yml      题目信息
├── README.md          题面
├── attachments/       附件
├── writeup.md         题解（默认隐藏，用户确认后才显示）
├── solve.py           解题脚本（持续集成中运行，确认能解出 flag）
└── build/             生成附件的脚本（附件可重新生成）
```

`challenge.yml` 示例：

```yaml
id: misc/zip-fake-encrypt-01
title: 打不开的压缩包
category: misc            # misc / stego / crypto / web / reverse / pwn / ics
chapter: "1.5.1"          # 对应教材章节
level: 入门               # 入门 / 基础 / 进阶
points: 100
tags: [ZIP, 伪加密]
tools: [forensics.zip_structure, forensics.zip_unfake]   # 题解中用到的工具
explainer: zip-fake-encrypt
flag:
  format: "flag{...}"
  sha256: "<flag 加盐后的 SHA-256>"
  salt: "<随机盐>"
hints:
  - 解压软件说需要密码，但真的加密了吗？
  - 看看 ZIP 文件里“通用位标记”这个字段。
license: MIT
author: DeepShawn
```

### 2.3 离线验证 flag

例题需要在没有服务器的情况下判断用户提交的 flag 对不对，同时不能把正确答案明文放在 App 里：

- 题目中只保存 `SHA-256(盐 + flag)` 和盐，不保存 flag 本身；
- 用户提交后，在本机计算 `SHA-256(盐 + 用户输入)` 进行比较；
- 每道题使用不同的盐，避免用同一张表反查多道题。

这种方式只能挡住“直接翻文件看答案”，挡不住有心人逐个尝试，但例题的目的是学习，这个强度已经足够。需要正式计分的比赛请使用靶场或专门的比赛平台。

## 3. 靶场（v1.x）

### 3.1 形式

每个靶场题目是一个 Docker Compose 项目，在用户自己电脑上的 Docker 环境中运行。工具包的“例题”页列出靶场题目，点击“启动”后通过本地运行器（见[计划总览 3.4 节](README.md#34-本地运行器可选)）启动对应的容器，显示访问地址；手机端可以阅读题面、提交 flag，通过已配对的电脑启动容器。

```
range/web/php-weak-type-01/
├── challenge.yml
├── README.md
├── docker-compose.yml
├── src/               题目源代码
├── writeup.md
└── solve.py           自动解题脚本（持续集成中启动容器并验证）
```

### 3.2 安全要求

靶场题目本身就是有漏洞的程序，必须与用户的电脑和网络隔离：

| 要求 | 做法 |
|---|---|
| 只在本机可访问 | 端口只绑定到 `127.0.0.1`，不对局域网开放 |
| 不能访问外网 | 题目容器放在 `internal: true` 的独立网络中 |
| 限制资源 | 每个容器设定 CPU、内存、进程数上限 |
| 不提升权限 | 不使用 `privileged`；PWN 题只在需要时添加 `SYS_PTRACE` 一项权限 |
| 用完即删 | 关闭题目时删除容器与数据卷 |
| 动态 flag | 每次启动生成新 flag，通过环境变量传入容器；提交时由本地运行器验证 |

### 3.3 首批靶场规划

与讲解、例题的编排对应，按教材章节逐步增加：

| 方向 | 首批题目 | 对应章节 |
|---|---|---|
| Web | HTTP 头部与 Cookie、信息泄露（`.git`、备份文件）、PHP 弱类型、文件上传（四种绕过各一题）、SQL 注入（联合查询、报错、布尔盲注、时间盲注）、文件包含与 `php://filter`、命令执行、XSS、SSRF | 4.0～4.9 |
| PWN | 按保护机制逐级开启的栈溢出系列：无保护 → 开 NX（ret2libc）→ 开 Canary（格式化字符串泄露）→ 开 PIE → 64 位；堆利用按 glibc 版本分组（2.23、2.27、2.31） | 6.2～6.4、7.5～7.8 |
| 工控 | 模拟 Modbus/TCP 从站（读写寄存器取得 flag）；模拟 S7 通信 | 8.2 |
| 攻防演练（远期） | 两个队伍各守一台服务，限时修补漏洞（练习教材 7.9 的打补丁技术） | 7.9 |

### 3.4 与教学的结合

- **教师模式**（远期）：教师从题库中选题组成一套练习，导出为一个文件分发给学生；学生在本机完成，导出完成记录交回。不需要搭建服务器。
- **社区投稿**：接受投稿的例题与靶场题目，投稿须原创并以 MIT 协议授权，附带可运行的 `solve.py`，通过持续集成验证后合并。是否开放投稿见[待决事项](README.md#10-待决事项)。
